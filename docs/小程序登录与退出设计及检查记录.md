# 小程序登录与退出设计及检查记录

2026-09-10 用户确认后实施，已追加底部定位、脱敏号码及任意验证码优化。范围仅为小程序手机号登录、身份关联与退出，不调整既有五个业务页面的内容布局，不增加注册、账号设置或商户选择页面。

## 页面与流程

- `merchant/index.html` 是唯一小程序入口。未登录时公共 shell 展示独立登录页面，规范地址为 `#login`，没有底部导航。登录是访问状态，不新增第六个业务导航。
- 登录页沿用公共蓝白主题、430px桌面预览外框、字号、按钮与底部弹层，主操作为“本机号码一键登录”，次操作为“短信验证码登录”。
- 一键按钮上方和授权弹层共用本机号码区，显示前三位、四个星号、后四位，如`139****0001`；号码来自同一适配器并与登录结果核对。号码缺失时禁用一键入口，保留短信登录，不展示错误号码。
- 公共底部弹层在`showModal`前完成定位，显式`top:auto; right:auto`，以手机框内缘确定left、bottom、width，消除原生dialog默认顶部定位的干扰。覆盖登录授权、退出确认及共用筛选弹层；正文自适应高度，保留顶部圆角、遮罩、底部安全区及窗口尺寸变化重定位。
- 一键登录：点击主按钮 → 手机号授权底部弹层 → 同意并获取号码 → 验证、关联商户 → 进入行业资讯。包含处理中、取消、失败重试和切换短信登录；授权取消或离页会取消待完成请求，迟到结果不能恢复登录。
- 短信登录：同页切换手机号/验证码表单，按钮与Enter统一提交。手机号和验证码均任意非空即可登录，不校验格式、长度、验证码有效期或错误次数，不要求先发送。发送按钮保留发送提示和60秒重发倒计时，仅用于展示；修改手机号仍清空验证码输入。
- 三个预置号码保持原商户，其余任意输入进入默认丰茂冻品商行。一键登录未知号码也进入默认商户；不创建新商户。保存和刷新会话共用该映射，取消未关联商户拦截。
- “我的”商户资料下方新增图标加文字的“退出登录”。确认弹层提供“取消”与“退出登录”，取消保留原会话；确认后返回小程序登录页。

## 身份与状态

- `merchant-auth.js` 提供独立认证状态与号码关联；`merchant-login.js` 提供登录页、授权和退出交互；`merchant-login.css` 仅补充移动登录布局，复用公共令牌和`merchantUI.sheet`。
- `merchantProfile.currentId()` 统一读取已登录商户。经营报告、建议及我的资料继续通过它读取身份；网址`?merchant=...`不能登录或切换商户。
- 按最新用户要求，原型登录状态使用项目路径隔离的`localStorage`键`frozen-mini-login-v2:<merchant目录URL>`。首次从Web入口打开需登录，后续同浏览器同地址的新标签、刷新或关闭后重开均自动进入，只有主动退出才再次登录；不设置自动到期或“记住我”开关。旧sessionStorage v1不读取，本次更新后首次登录写入新格式。
- 存储不可用时仅保留当前页面内存状态，刷新需重新登录。清除浏览器数据、更换浏览器/浏览器用户目录或访问地址也需要重新登录。没有真实认证或安全保证；技术边界仅记录在开发文档。
- shell在初始进入、hash路由变化、历史返回、BFCache恢复和业务操作前校验状态，回到前台时再次检查，不再设置24小时到期计时。storage事件同步同地址多标签页的登录与退出，阻止退出前尚未完成的登录请求重新写入状态。未登录不挂载业务页。离页清理登录请求及业务监听。
- 退出清除小程序会话和验证码记录，清空页面、详情历史映射、筛选状态和当前内存中的业务投影；不删除按户隔离的历史阅读记录和发布缓存，不影响管理端会话。详情键保持单调递增，避免同一页面中旧历史键匹配到新登录后的详情。
- 旧文中“小程序直接进入默认商户”“网址参数确定商户”的规则由本次登录方案替代。保留历史嵌入数据接收代码，但同样经过商户登录，不新增管理端预览入口。
