# 长内容详情与记录页面统一优化

## 范围与完成项

2026-09-11，用户确认按前一轮梳理统一优化长内容详情，并将相邻的长表单纳入同次改造。

| 模块 | 页内查看或操作入口 |
| --- | --- |
| 市场行情简报 | 简报详情、版本与过程记录、历史版本全文 |
| 商户经营报告 | 报告与建议详情、版本记录、引用的市场简报 |
| 行业资讯 | 非待核验资讯详情与记录；待核验继续使用已有核验工作台 |
| 行业资讯来源 | 来源详情与确认、独立获取记录页 |
| 每周平均采价 | 详情与历史、批次列表、批次详情、批量导入 |
| 品类映射 | 名称归并、业务数量及历史价格关联详情 |
| 市场量价分析 | 图表数据点和明细按钮对应的量价明细 |
| 简报及经营报告计划 | 按周/月切换的生成记录页 |
| 追溯记录 | 过程详情、原版本关联查看、操作前后对照 |
| 系统管理 | 用户详情、角色详情、角色新增及编辑 |

资讯获取设置只保留来源概要、规则、周期和启用选项；最近执行情况、重试说明、获取历史移入独立“获取记录”入口。资讯发布确认仅显示标题、来源、分类位置和版本等必要信息，不再重复整篇正文。短表单、状态切换和发布确认继续使用公共dialog。

## 公共页面与返回

`ui.js:openTaskWorkspace`扩展为同模块多层工作台，`openDetailPage`复用同一实现提供整页只读或表单界面。每层记录上一层DOM、进入前滚动和触发焦点。打开下级时隐藏上一级，返回时恢复；列表页签、查询草稿、已执行条件和页码不因查看详情重建。报告、简报仍按传入版本与冻结快照展示。

查看链路覆盖“版本记录→版本正文”“经营报告→引用简报”“追溯过程→关联版本”“采价历史/批次列表/导入结果→批次详情”。编辑页进入只读参考页时保留原表单和未保存状态；返回只读页不提示放弃父页修改。多层浏览器返回与外部导航检查涉及的未保存表单；离开路由统一销毁各层，释放获取/生成记录订阅。读写表单沿用原业务保存接口和版本冲突校验。

`openDetailPage`提供`close`、`open`及`close`事件用于延续既有表单、文件读取和订阅生命周期。页面内关闭按钮走取消保护；业务校验成功后调用`close`完成返回。导入关闭会使尚未完成的读取失效，成功结果保留页内展示并可进一步查看批次；导入成功后清除未保存标记。

## 布局

- 只读页以全宽内容卡片呈现，不预留空侧栏，不添加无操作意义的底部取消栏。
- 元数据三列紧凑排列，窄屏降为两列或单列；正文、表格与权限配置使用主要宽度。
- 资讯原文和展示稿、追溯前后留存、版本文字修改前后采用并排对照，手机宽度下上下排列。
- 导入预览和角色权限树取消原弹窗内的固定高度限制；表格保留横向滚动。
- 获取与生成记录自动更新时，依据记录标识保留已展开的明细。
- 三处长文本编辑继续使用上一轮1.6:1左右布局、摘要紧凑/长正文放大及参考栏等高滚动规则。

## 验证边界

按项目约定仅执行静态与Node检查，不启动服务、不打开浏览器、不做截图验收，不提交Git。专项检查覆盖父子详情返回、编辑草稿与滚动留存、多层离开确认、监听与订阅清理；其他受影响模块继续运行现有业务回归检查。静态检查不能代替实际渲染、滚动与浏览器历史行为验收。
