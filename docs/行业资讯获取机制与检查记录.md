# 行业资讯获取机制与检查记录

## U07 · 用户确认范围（2026-09-10）

用户确认在现有“行业资讯 → 来源管理”补充按来源配置的定期获取、立即获取、最近与下次执行情况，以及获取记录。来源确认、资讯逐篇核验和人工发布相互独立。沿用原路由、公共页签、组件与样式，不新增菜单，不改独立小程序数据入口。

## 页面与操作

- 来源列表增加“获取配置 / 下次获取”和“最近获取”列，显示状态、周期、下一次执行时间、最近时间及新增/更新/重复/失败数量；原来源更新时间仍保留在维护记录中。
- 行内“获取设置”使用公共弹窗，包含获取规则、周期和“启用自动获取”开关，展示当前执行情况和获取历史。按钮统一图标加文字，来源操作区局部换行，表格沿用公共横向滚动。
- “立即获取”直接执行，执行中显示“获取中”并禁用重复点击；未确认来源、未配置规则时禁用。获取成功后可点击“关联信息”查看新增的待核验资讯。
- 获取记录包含批次、触发方式、尝试次数、检查期间、执行人及新增/更新/重复/期间外跳过/失败数量；错误原因保留在记录中。资讯详情增加获取时间和批次，原文链接及发布时间继续独立展示。
- 原列表的选择即查询、文本按钮或 Enter 查询、查询保持、分页及来源限定行为保持。未添加获取状态筛选。

## 周期与启动条件

时区统一为北京时间，按每个来源配置，不根据文章分类强制决定周期。

| 周期 | 执行时间 | 初始应用 |
| --- | --- | --- |
| 每日两次 | 09:00、16:00 | 普通政策及行业资料来源 |
| 每2小时 | 08:00、10:00、12:00、14:00、16:00、18:00、20:00 | 更新较频繁的供需、行情来源 |
| 每日一次 | 09:00 | 周刊等更新较少的来源 |

关闭自动获取即按需手动获取，保留周期配置。自动获取只在来源已确认、规则有效且绑定当前来源地址时启用。初始9个来源已配置栏目规则，已确认来源启用对应默认周期；待确认来源保持关闭，初始不虚构已完成的获取记录。

新增来源默认未配置规则、未开启自动获取，可保存为待确认；确认并配置后才可执行。来源地址不是完整采集配置，需选择栏目或接口规则。修改网址清除规则、关闭自动获取，并重置该地址的增量游标，需重新配置；其他来源资料修改仍按原逻辑待确认、资讯重审及暂停发布。单纯修改周期或自动获取开关只记获取配置历史，不修改来源业务版本，不让已核验或已发布资讯失效。

## 内容处理与审核

1. 首次检查近30天，成功后记录获取游标；后续从最近成功游标向前重叠1天检查，避免临界内容遗漏。增量参数提供给读取适配器；获取到的既有文章即使原发布时间较早，也可识别其原文变化。
2. 同一来源按文章编号或规范化原文链接去重（去除链接片段）。无变化只计重复，不改原核验、发布及历史。新文章必须具有标题、正文、原文时间、原文链接和来源范围内的品类；新文章落入待核验，默认分类取当时来源配置。
3. 已有原文发生变化时保留前后快照和历史发布版，更新当前原文及展示稿，清除通过结论与当前发布，重新待核验；已人工确定的文章分类继续保留。更新后需重新核验，再单独人工发布；历史原文与历史发布内容不被覆盖。
4. 未来内容及首次窗口之前的未知内容跳过。字段错误计失败，其他有效内容可入库，但整批游标不前移；重试时已入库内容去重，不重复生成。
5. 获取失败不修改既有文章的核验或发布状态。已启用自动获取时，初次失败5分钟后重试，第二次失败15分钟后重试，最多2次；三次尝试均失败则停止该来源自动调度，显示获取异常并等待人工重试。关闭自动获取不安排自动重试；手动重试成功后恢复下一个正常周期。
6. 同一来源的并行点击不创建重复任务；执行中来源版本或配置变化，丢弃过期结果。退出登录后不允许新获取/配置修改，尚未写入的在途结果取消。

## 技术边界

这是静态 HTML/JS 原型。`source-collection.js` 的读取适配器使用业务合理的虚构文章，不访问任何来源网站、不发送接口请求，不代表真实栏目解析或接口连通性已验证。真实接入需要后端调度与对应网站/接口适配器；本轮没有授权或实施这些工程。

管理端完成登录、公共 shell 渲染后启动一个30秒检查器，按每个来源的下次时间触发，切换管理端菜单不重复启动。调度器只在当前管理端页面存续期间运行；关闭页面不在后台采集，浏览器休眠可能推迟执行，恢复后按到期状态执行一次，成功后计算下一个周期，不逐次回放错过的时点。获取处理延迟650ms展示执行状态。

来源、获取配置、游标、文章及获取记录在本次页面会话中保留，刷新恢复初始数据；不新增本地存储或后台持久化。上述技术边界仅记录在开发文档，业务页面不显示演示或缓存实现文案。独立小程序继续其既有预置内容，管理端公开发布投影沿用原机制，不声称独立端实时同步。

获取记录写入来源现有 `history`，资讯入库和更新写入文章现有 `history`。统一追溯直接复用这两处历史，补充获取配置与批次字段，不新增第二份日志存储；页面订阅在路由切换及弹窗关闭时清理。
