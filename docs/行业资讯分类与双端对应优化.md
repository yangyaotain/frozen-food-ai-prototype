# 行业资讯分类与双端对应优化

## U06 · 用户确认范围（2026-09-10）

将管理端“外部数据源”改名为“行业资讯”，保留 `admin:sources` 路由及原模块，不新增菜单。公共页签调整为“资讯管理、来源管理”，默认进入资讯管理。对应小程序“行业资讯”下的政策信息、行业资讯、供需行情三个分类。

本轮只落实上述资讯模块方案。不恢复已移除的商户资讯预览，不修改其他模块的发布数据入口，不接入真实采集或后端。独立小程序仍使用已有预置数据，本轮分类一致性不代表管理端发布已实时同步到独立小程序。

## 页面对应

| 管理端 | 小程序 | 规则 |
| --- | --- | --- |
| 资讯管理 · 政策信息 | 行业资讯 → 政策信息 | 来源确认、逐篇核验通过后人工发布 |
| 资讯管理 · 行业资讯 | 行业资讯 → 行业资讯 | 同上 |
| 资讯管理 · 供需行情 | 行业资讯 → 供需行情 | 外部消息与供需观察文章 |
| 市场行情简报（既有） | 市场行情（既有） | 平台量价周报、月报；不与供需资讯混合 |

管理端资讯列表新增分类及发布状态筛选，选择立即查询并读取当前关键词，查询按钮及 Enter 使用同一表单提交逻辑。核验状态、发布状态继续分列，发布状态分为未发布、待发布、已发布、暂停展示。分类标签复用公共 badge；列表和详情采用当前展示标题，保留原文标题、正文和历史。

“发布时间”明确为“原文发布时间”；平台发布时间随发布记录留存，在详情的核验及发布过程记录中显示。发布弹窗明确“小程序 → 行业资讯 → 所选分类”、适用品类及版本。各页签保留自己的查询状态，Home 定位资讯管理，End 定位来源管理。

## 分类与版本

- 公共 `category-catalog.js` 扩充 `newsTypes` 分类字典，管理端表单、资讯公开数据校验、小程序筛选及标签共用，分类 ID 保持 policy / industry / market。
- 来源的 `type` 在界面显示为“默认资讯分类”；初始化文章时将其保存为文章自身 `item.type`。整理展示稿提供必填分类单选，允许同一来源的不同文章属于不同分类。
- 修改来源默认分类不会覆盖已有文章分类；仍按既有来源变更规则重新确认来源、关联资讯重新核验并暂停原发布。
- 分类变更与展示稿变更执行同一校验及留档流程：需填写处理依据，信息版本递增，清除当前通过结论，暂停当前发布。无变化保存保持状态；空分类、非法分类及过期版本请求均拒绝写入。
- 核验通过不自动发布。人工发布读取文章自身分类，将其冻结到公开发布快照；旧版分类及原文不被后续变更覆盖。未传入分类的旧代码调用保留文章当前分类，兼容既有文字整理流程。
- 本模块详情及追溯记录区分“默认资讯分类”和“资讯分类”，分类变更前后及旧发布分类可追溯。追溯模块显示名同步为“行业资讯 · 来源管理／资讯管理”，不改历史数据。

## 验证

新增 `scripts/check-news-classification.mjs`，验证公共分类、文章与来源分类独立、组合筛选、仅改分类后重审、人工重新发布、原文及历史快照保留、非法及过期请求、无变化保存，以及编辑分类字段和发布位置。

更新 `scripts/check-source-experience.mjs`，验证默认页签、分类及发布状态即时筛选、查询条件保留、页签键盘顺序、原文时间标签，并保留原来源维护和发布暂停检查。

最终结果：19 项 Node 专项检查全部通过；`scripts/check.mjs` 检查 100 个文件、14 个路由定义通过，覆盖脚本语法、本地资源、UTF-8、空白及基础 CSS。包含采价、品类映射、资讯、分析、简报、报告、小程序、系统管理与追溯回归。

按项目约定仅运行 Node 行为检查和静态检查，不启动服务或浏览器，不做截图、布局或渲染字号对照。工作区不是 Git 仓库，不能运行 `git diff --check`；使用项目静态检查验证空白、语法及资源引用，不初始化 Git、不提交或部署。
