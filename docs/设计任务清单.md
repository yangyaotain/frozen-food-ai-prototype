## 工作方式

1. 按任务编号逐步推进，每次限定一个交付包，先理解相关页面和依赖，再实施。
2. 每包说明页面范围、主要字段、交互状态和验收点；必要的业务问题在对应模块解决，不要求一次性补齐全部资料。
3. 复用公共导航和设计令牌；公共组件在首次使用时补齐，后续复用，不提前创建无用途的组件。
4. 所有示例商户、价格和经营数据均为虚构演示数据。相同品类、期间、报告和版本共用一致标识与数值。
5. 每包完成后更新本清单及需求映射、接续说明；报告静态检查结果，不将其描述为浏览器验收。
6. 默认不启动服务、浏览器或真实 AI，不提交 Git、不推送、不部署。

## T01：每周平均采价——列表与查询

目标：完成首个可使用的列表页，确定后续维护类页面的视觉和交互基线。

- 页面入口：管理端 `prices` 路由，继续使用公共菜单和顶部导航。
- 页面结构：标题与简短说明、查询区、采价表格、结果数量与分页。
- 查询条件：采价周、分析品类、复核状态、品类关键词。
- 表格字段建议：采价周及日期范围、分析品类、周均价格、单位、复核状态、维护人、更新时间、操作。
- 价格语义：维护的是询价后的周平均价格，不将单次报价冒充周均价。
- 示例品类先使用需求中的鸡副、水产、猪副，明确仅为演示样例，不视为完整品类清单。
- 示例价格可暂按人民币元/吨展示并注明演示单位；正式单位在本模块实施时核对，不能混合单位直接比较。
- 公共组件：查询控件、主次按钮、表格、状态标签、分页、空状态和必要图标。
- 查询规则：选择或清除条件立即查询，并使用当前文本；输入文字不自动查询；查询按钮和 Enter 结果一致；重置清空条件并更新结果。
- 分页规则：查询条件改变后回到第一页；无结果时展示空状态，不残留上一次表格内容。
- 本包不放置无法使用的新增、导入等按钮；相关入口随 T02 一起实现。

验收点：公共导航保持一致；条件组合与分页状态正确；按钮为图标加文字；字段与单位明确；完成脚本和资源引用静态检查。
