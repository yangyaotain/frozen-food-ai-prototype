## 页面与控件

- `shell.js` 继续从 `config.js` 生成同一份商户导航。商户使用精简顶栏、统一详情返回和底部四项导航；保留当前工作区的登录入口及管理端公共顶栏更新。
- `merchant.css` 仅由商户入口加载，继承项目蓝白主题、字体与字号令牌。页面宽度上限430px，内容自然排布，底部导航预留安全区；常用控件和选项使用至少44px点击区域。
- `merchant-ui.js` 提供分类切换、底部选择面板、详情层及空状态。月份选项来自已有内容的覆盖月份；超过10个选项时出现关键词搜索。面板支持关闭、Escape、点遮罩关闭和焦点恢复。
- 选择或清除后立即查询；资讯文本输入只在查询按钮或Enter提交时查询。更改分类时同时使用输入框当前内容。来源搜索同时匹配原始名称及工作区公共展示名称。
- 列表每次显示4条，“加载更多”追加4条。进入详情后隐藏筛选；返回保留筛选、已加载数量和浏览位置。切换路由清理监听、定时器、弹层及图表观察器。

## 数据与发布边界

1. **独立打开商户入口**：加载离线预置快照，无需先操作管理端。公开资讯/行情使用`assets/js/demo/public.js`；本户报告仅按白名单商户ID加载对应的`demo-a.js`、`demo-b.js`或`demo-c.js`，不同时加载全部商户。没有商户切换控件；无效ID不给其他商户数据。
2. **管理端嵌入预览**：继续请求本次管理端发布投影，仅接收父窗口和对应消息类型；本户报告还核对商户ID及内容结构。首次同步前不展示旧缓存。未发布、暂停、空数组、同步失败均不回退到独立快照。未复核内容仍不能发布，来源异常仍按既有规则撤下资讯。
3. 独立快照报告/阅读记录使用`mini-demo-v1:`存储前缀，不写入管理端缓存或普通发布缓存。报告与建议阅读版本独立记录；阅读旧版不会清除新版提示，选择“查看最新版本”后才切换。
4. 同版报告与建议互跳保留当前快照。引用行情通过手机宽度详情层展示生成时引用版本，不自动替换成后续版本。
5. 快照由`node scripts/build-merchant-demo.mjs`在独立Node上下文中通过已有采价复核、逐篇资讯发布、简报发布、报告建议共同复核与发布校验生成，再做白名单投影。该构建不连接浏览器、不读写管理端本地缓存、不执行真实业务发布。只在需要重建实例数据时手动运行。
6. 全部业务数据仍为虚构；当前工作区另有`presentation.js`统一展示文案，本次沿用其显示名称，不修改数据ID和版本。原型不是微信小程序工程，不构成真实账号隔离或多用户同步。
